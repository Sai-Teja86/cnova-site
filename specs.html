Appliance

FormSelf-hosted virtual or physical appliance, installed from one ISO. No internet needed to install
Operating systemDebian 12, hardened: root locked, firewall drops everything not listed under Network, the server screen shows a menu console instead of a login prompt
HypervisorsVMware, Microsoft Hyper-V (generation 1 and 2), Proxmox, KVM, Nutanix AHV. Guest tools included
PhysicalAny x86-64 server, BIOS or UEFI, Secure Boot supported
Minimum2 vCPU, 4 GB memory, 40 GB disk
Recording storageExtra disk for recordings, sized to your session volume and retention period. Remote desktop recordings take the most space
SizingSized with you during the trial, from your number of users, concurrent sessions and retention needs
Unique per installMaster key, TLS certificate, SSH host key and database are made on first start. Nothing secret is on the installer
IntegrityEvery installed file is listed in a signed manifest, checked at start-up and daily; a mismatch is audited and restricts the appliance
ManagementWeb console for everything; the server screen offers network, host name, time, license and update tasks

Supported targets

SessionsSSH, RDP, VNC; SFTP, SCP and rsync through the SSH gateway; Windows RDS RemoteApp programs
ServersLinux and Unix over SSH; Windows local accounts over SMB; Windows domain accounts in Active Directory over LDAPS
DatabasesMicrosoft SQL Server, Oracle Database, MySQL, MariaDB, PostgreSQL, MongoDB, Redis and Valkey, Apache Cassandra, SAP HANA
Network and securityCisco IOS and IOS-XE, Fortinet FortiGate
Anything else over SSHCustom platforms: rotation written as send-and-expect steps, without waiting for a release
ApplicationsAny program published on a Windows RDS server, optionally signed in with a second vaulted account

Supported systems lists how each platform's password is changed, and what is planned.

Encryption and keys

Stored secretsAES-256-GCM envelope encryption: a fresh data key per secret, wrapped by the appliance master key. Each ciphertext is bound to its record as associated data
Secret historyEvery version kept, encrypted the same way, with who changed it and when
Keystroke logsEncrypted with a key derived from the vault
BackupsAES-256-GCM in authenticated chunks; key from your passphrase with scrypt (N=217, r=8, p=1). The passphrase is never stored
Encrypted recording downloadsAES-256-GCM. Key from HKDF-SHA256 over a PBKDF2-SHA256 passphrase key (600,000 rounds) and a part held only by the appliance that made the file
Audit trailEach event chained to the one before with HMAC-SHA256
RecordingsSHA-256 of each recording sealed into the audit trail; checked on every replay and before compression replaces the original
User passwordsArgon2id
API keysOnly a hash is stored; the key is shown once
Updates and licensesEd25519 signatures, checked before anything is installed or accepted
In transitHTTPS to the console; SSH to targets with host keys pinned on first use; RDP with certificate validation on by default; LDAPS or StartTLS with certificate checks

Sign-in and identity

SourcesLocal users; any number of Active Directory and LDAP domains; OpenID Connect providers (authorization code with PKCE)
Multi-factorTOTP authenticator apps. On by default for the first administrator; can be required for everyone
Directory usersCreated on first sign-in; role from directory groups at every sign-in; groups usable directly in policies
Directory syncEvery 15 minutes: leavers disabled, group changes followed, sessions no longer allowed are ended
RolesAdministrator, approver, auditor, user
Console sessionEnds after 30 minutes idle, and after 12 hours however active
Lockout5 failed attempts lock the account for 15 minutes
Local passwordsAt least 12 characters; changed at first sign-in
Sensitive settingsChanging downloads, retention and similar settings asks again for the administrator's password and MFA code

Brokered sessions

ClientsAny modern browser (nothing to install); native SSH clients through the gateway
Credential handlingInjected by the gateway; never sent to the user's browser or computer
Session startSingle-use ticket valid for 30 seconds; the policy is checked again at connection
Idle timeout15 minutes without input
Maximum lengthSet per policy
Command controlRegular-expression blocklists per policy for Linux shells and Windows cmd and PowerShell over SSH, chained commands included
Keyword guardBlocked words typed in RDP, VNC and application sessions warn or end the session, per policy
ClipboardAllowed or blocked per policy
File transferUpload and download as separate rights, off by default. Blocked types checked by file contents; blocked words checked inside text, Office and zip files; up to 2 GB per session upload
PrintingDisabled in remote desktops
MonitoringLive read-only view and immediate termination, by administrators and auditors

Recording

What's recordedSSH, RDP, VNC and application sessions, by default. Switch off per server, for example test and UAT systems
FormatsSSH in asciicast v2 text; remote desktops in the graphical session protocol. Both replay in the browser with seeking
IndexingCommands and typed lines searchable across all recordings
Kept outPasswords typed by Vaultgate, and the contents of transferred files
Compressiongzip, replacing the original only once the compressed copy has been checked against the sealed hash
RetentionOff until an administrator sets a period; a preview shows what would be deleted
Disk protectionAlerts as space runs low; new sessions refused before the disk fills, never run unrecorded
DownloadsOne setting: off, plain evidence package, or encrypted (default). Encrypted files open only on the appliance that made it, or its standby or restored copy, with each opening audited

Audit and reporting

EventsEvery sign-in, policy decision, request, approval, credential reveal and fetch, session, rotation, file transfer and configuration change
Tamper evidenceHMAC-SHA256 chain with a one-click integrity check
ViewsSign-ins, sessions, credentials, access, identity, configuration; session activity per command
ExportsCSV of every view; PDF management report with charts and findings

Password rotation

ScheduleEvery N days, after each use, on demand, or any mix, through named rotation policies
Generated passwords12 to 128 characters (24 by default), symbols on or off, characters to avoid
MethodsBy the account itself, or through a control account for accounts whose password nobody knows
CheckingEvery new password is tried with a real sign-in; a failure is flagged as unverified with the reason
Lockout safetyIf a target rejects the current password, automatic rotation of that account pauses instead of retrying
SchedulerChecks for due accounts every minute

Personal JIT accounts

WhereLinux and Unix servers, Windows servers (local accounts), Active Directory (domain accounts allowed only on the covered servers), SQL Server, Oracle, MySQL, MariaDB and PostgreSQL
LifecycleCreated at the user's first connection, with the groups or roles in the policy; removed 10 minutes after the last session ends or when access is withdrawn; failed removals retried every 5 minutes
PasswordRandom, held in the vault, never shown to the user
TrackingEvery creation and removal audited; accounts marked as Vaultgate JIT accounts on the target; an administrator page lists them all

Credential API

EndpointsGET /api/v1/credential (one account by id, name, address, user name or tag) and GET /api/v1/accounts (what the key may fetch)
AuthenticationAuthorization: Bearer API key, one per application, optional expiry up to 10 years
RestrictionsAllowed source addresses; exact accounts or tags; optional mandatory reason
Rate limitPer application, 120 requests a minute by default, up to 6,000
Abuse protection10 failed requests from one address within 5 minutes block it for the rest of that window
Never releasedControl accounts and personal JIT accounts

Email notifications

TransportYour mail server or relay: STARTTLS, implicit TLS, or unencrypted to an internal relay without sign-in
CertificatesChecked by default; an internal CA can be added
Sign-inOptional; the password is sealed like vault secrets
To peopleNew access requests to each approver; decisions to the requester
AlertsRotation failures, JIT removal failures, disk space, integrity and audit chain, license, failover and standby sync, keyword-guard terminations; each can be switched off
GroupingFurther alerts of one kind within an hour sent as one summary
DeliveryBackground outbox, retried for 24 hours; console warning while email isn't getting through; every send audited
ContentNo passwords, keys, recordings or command output; approval always needs a sign-in

Availability, backup and updates

FailoverPrimary, warm standby and a small witness appliance. A virtual address moves to the standby about 45 seconds after the primary fails
Split-brain protectionThe witness grants one lease at a time; a replaced primary never serves again until it rejoins; a primary cut off from both others stops rotating passwords
Standby copyEncrypted backup sent after each change; recordings copied daily
BackupsEncrypted, with or without recordings; restored onto a new appliance from the setup wizard
Recovery kitEmergency accounts in an encrypted file that opens offline, unlocked by a set number of recovery codes (for example 2 of 3)
UpdatesSigned bundles, checked before install, rolled back automatically on failure. A pair updates the standby and witness first. Security fixes install regardless of support dates

Offline activationRequest file out, signed license file in, for isolated networks
Updates entitlementReleases made during the support period install; security fixes always do
