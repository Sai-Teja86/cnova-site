What Vaultgate does

Everything a team needs to control who reaches its most sensitive systems, and to prove it afterwards.

🔐

Credential vault

Passwords and keys sealed with AES-256-GCM, one key per secret. Every version is kept, and checkout comes with a reason, a time limit and an exclusive lock.

🔄

Automatic rotation

Passwords change on a schedule or after each use, and Vaultgate signs in with the new one to prove it works. Named policies set length, symbols and timing.

🖥️

Brokered sessions

SSH, RDP and VNC open in the browser through the gateway with the password injected. Native ssh, scp and sftp work through the same gateway.

🎬

Recording and search

Every session is recorded and replayed in the browser. Commands and typed lines are indexed and searchable, and each recording is sealed so tampering shows.

🛑

Command control

Block dangerous commands before they reach the server. Clipboard and file transfer are separate permissions, and blocked file types and words are stopped in both directions.

👁️

Live oversight

Auditors watch live sessions read-only. Administrators end any session at once, and idle sessions close on their own.

⏱️

Just-in-time access

Users ask for access with a reason and a duration. An approver decides, nobody approves their own request, and access ends on time.

🏢

Your directory

Active Directory and LDAP domains, OpenID Connect single sign-on, roles from directory groups, and TOTP multi-factor sign-in. Leavers are disabled at the next sync.

🔎

Discovery and onboarding

Find computers and privileged accounts in Active Directory, discover local Windows accounts, or import a CSV. New accounts get a fresh password straight away.

🔗

Credential API

Scanners, pipelines and scripts fetch passwords over HTTPS when they need them, so rotation never breaks them. Each application has its own key, addresses and accounts.

🪟

Application access

Published RemoteApp programs, such as SQL Server Management Studio or AD Users and Computers, open as a single window in the browser and sign in with a vaulted account.

📜

Tamper-evident audit

Every sign-in, decision, reveal and change goes into an HMAC-chained log you can verify. Export it as CSV, or as a PDF management report with charts.

How it works

Users never hold the password. Vaultgate signs in for them, and watches the whole session.

  1. 1

    Sign in

    The user signs in with their directory account or single sign-on, plus a second factor.

  2. 2

    Policy check

    Access is denied unless a policy allows it: by user, role or group, with time windows and optional approval.

  3. 3

    Brokered session

    The gateway takes the password from the vault and signs in to the server. The user's browser never receives it.

  4. 4

    Record and rotate

    The session is recorded and sealed into the audit trail. The password can change as soon as the session ends.

Built for security teams

Secrets at rest

Every credential is sealed with its own key, wrapped by a master key that each appliance generates on first start. The database alone is useless without it.

No shared secrets

Each installation makes its own master key, TLS certificate, gateway host key and database. Nothing secret ships on the ISO.

Pinned host keys

Target host keys are pinned on first use. A changed key blocks connections and is logged until an administrator checks it.

Signed updates

Updates are signed bundles. The appliance checks the signature before it installs anything.

Failover

A primary, a warm standby and a witness. The virtual address moves to the standby about 45 seconds after the primary fails.

Recovery kit

Emergency accounts in one encrypted file that opens offline in a browser, unlocked by a set number of recovery codes, for example 2 of 3.
