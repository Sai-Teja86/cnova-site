Getting Vaultgate

Vaultgate is self-hosted: it runs on your own VM or server, and your credentials, recordings and audit trail never leave your network. Cnova doesn't host your data.

Trial

Request a trial and we send the installer with setup help. Every new appliance runs for 30 days without a license.

Customers

Installers and updates are delivered by Cnova for each release, made for your organization. Check each file against the SHA-256 listed here before using it.

Signed updates

Every update is signed by Cnova. Appliances refuse a file that was changed or didn't come from us, and go back automatically if a new version doesn't start properly.

Release history

0.1.0-54

28 Nov 2026Maintenance
  • Internal groundwork, with no change to what you see or how the appliance works. Installing it is optional.

0.1.0-53

28 Nov 2026Maintenance
  • Internal groundwork, with no change to what you see or how the appliance works. Installing it is optional.

0.1.0-52

27 Nov 2026New
  • Clocks of paired appliances. Requests between a primary, its standby and the witness are refused when their clocks differ by more than 5 minutes. The refusal now says which clock is off and by how much, and the Standby page shows each appliance's clock against this one, warning before the limit.
  • Set the date and time at the text console, for a standby or witness on a network with no NTP server.
  • The Time page shows times in your own time zone as well as UTC.

0.1.0-51

27 Nov 2026New
  • Configuration page. One menu item under Administration opens a page of cards for Control accounts, Credential API, Access Policies, Password Policies, Custom platforms, Users and Security Providers, each with a short description.
  • Clock set by hand. The Time page shows "Set by hand" when the clock was set from a browser and no time server answers, with a reminder that NTP is still needed.
  • Network tools. The port check offers the ports Vaultgate uses, from SSH and RDP to databases, directories, mail and syslog, and picking an asset selects its port.

0.1.0-50

27 Nov 2026New
  • Network tools. A new page in the appliance console runs ping, traceroute, a port check and a DNS lookup from the appliance, to find out why a server can't be reached. Pick an asset to fill in its address and port; results appear as they come, and each check is audited.
  • A clearer access policy editor. Policies are now made on a page of their own, step by step: who, to what, how, when, and optional session restrictions. Options appear only when they apply, and a summary says in plain words what the policy will allow.
  • Assets and Accounts. The Vault opens into separate Assets and Accounts pages, each with a search box.
  • Password Policies page. Rotation policies have their own page, where each policy chooses its accounts, searchable by name, asset or tag.
  • Regrouped menu (Workspace, Administration, Configuration, Oversight, Appliance) with an icon for each page, so the collapsed menu still shows where each link goes.
  • Set the clock from your computer. Where no time server can be reached, the Time page sets the appliance's clock from your browser's, to within about a second. It's refused while the clock is synchronised, and audited.
  • The landing page has the sign-in form beside the introduction.

0.1.0-49

26 Nov 2026New
  • Sign in from the first page. The landing page has the sign-in form beside the introduction. Sign-in errors and the authenticator code step stay in the same panel.

0.1.0-48

26 Nov 2026New
  • Log forwarding to your SIEM. Every audit event goes to your syslog collector or SIEM as it happens: RFC 5424 syslog with a JSON body, over TLS, TCP or UDP. Each message carries the event's tamper-evident chain hash, so your SOC's copy can be checked. While the collector is unreachable, events wait on the appliance and are sent in order once it's back. Set it up in the appliance console under Log forwarding.
  • Time page. See whether the appliance clock is synchronised, its offset and each NTP server's state, and set the NTP servers from the web console, with NIC and NPL's servers in one click. Losing sync raises an alert, as CERT-In's directions expect synchronised clocks.
  • Recording retention of at least 180 days. Retention can no longer be set below 180 days, in line with CERT-In's log retention. Shorter periods set earlier are raised to 180 days, and the change is audited. The audit log itself is never deleted.
  • Email alerts for log forwarding failures and clock problems.

0.1.0-47

26 Nov 2026New
  • Email notifications through your own mail server (STARTTLS, TLS or an internal relay, with the server's certificate checked). Set them up in the appliance console under Notifications, and send a test message that shows exactly what your mail server answered.
  • Who gets what: new access requests go to each approver, decisions to the requester, and alerts to the addresses you choose: failed password rotations, personal accounts that couldn't be removed, low disk space, failed integrity checks, license warnings, failover and standby problems, and sessions ended by the keyword guard. Each event can be switched off.
  • Alerts of one kind within an hour arrive as one summary. Emails that can't be sent are retried for a day, and the console warns while email isn't getting through.
  • Emails never contain passwords, keys or recordings, and approving a request always needs a sign-in.
  • Fix: the Credential API no longer hands out the passwords of personal JIT accounts.

0.1.0-46

26 Nov 2026New
  • Personal JIT accounts. Instead of a shared account, a policy can give each user, vendor or contractor their own account, jit-<username>, created when they connect and removed when their access ends or is revoked. Its password is random and never shown: Vaultgate signs in with it, and the server's own logs show who it was.
  • Servers: Linux and Windows local accounts, in the groups the policy lists. Live sessions end and, on Linux, the user's processes and home folder are removed afterwards.
  • Active Directory: one domain account per user in an OU you choose, allowed to sign in only to the servers the policy covers, deleted afterwards.
  • Databases: a personal login on SQL Server, Oracle, MySQL, MariaDB and PostgreSQL with the listed roles. Applications such as database consoles on RDS can put in each user's own login instead of a shared one.
  • Vaultgate never takes over or deletes an account it didn't make. The Vault page lists personal accounts with Remove now and Check server.

0.1.0-45

26 Nov 2026New
  • Recording per server. Turn recording off on an asset, for example test and UAT servers, to save space. Those sessions are still audited, command-indexed, filtered and can be watched live. The CSV import has a new record column.
  • Recording downloads setting on the Storage page: encrypted (default), plain evidence package, or off. Changing it needs the administrator's password and MFA code.
  • Encrypted recordings open only where they were made. A downloaded .vgrec file needs its passphrase and a key that stays on the appliance: it opens only on that appliance, its standby, or one restored from its backup, under Sessions → Open recording file. Every opening is audited.
  • Appliances that update switch to encrypted downloads by default; administrators can choose plain again on the Storage page.

Support and updates

Version numbers

0.1.0-44 is the product version followed by the build. A higher build is always newer, and appliances only ever move forward.

Update entitlement

Your license includes updates released up to its update date. Security-fix updates install on licensed appliances regardless of that date.

Operating system

Appliances run Debian 12. With internet access they install Debian security updates on their own; offline appliances get them in our update bundles.
