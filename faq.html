FAQ

Common questions

Can't find your answer? Ask us.

What is privileged access management?

Privileged accounts, such as root, Administrator, database owners and device admins, can change anything on a system. Privileged access management keeps their passwords in a vault, changes them regularly, controls who may use them, and records what is done with them.

Does Vaultgate run in the cloud?

No. Vaultgate is self-hosted: you install it on your own VM or server, and your passwords and recordings never leave your network. The only outbound call it needs is a daily license check-in, and it keeps working for 30 days without one.

Can it run on a network with no internet at all?

Yes. Use offline activation: the appliance shows a request code, we send back a license file made for that appliance, and you install it on the License page. It needs no check-ins and works until your license expires.

Do users need to install anything?

No. SSH, RDP, VNC and published applications open in a normal web browser. People who prefer their own tools can use any SSH client, scp or sftp through the SSH gateway.

Do users ever see the passwords?

Not in brokered sessions: Vaultgate signs in for them. If a policy allows someone to reveal a password, the reveal is audited, and the password can change automatically when they check it back in.

Do I need to know the current passwords to onboard accounts?

No. With a control account on the server or in the domain, Vaultgate sets a fresh password for each account as it is imported, so the old one stops mattering.

What happens if the Vaultgate appliance goes down?

With failover, a standby takes over the virtual address in about 45 seconds. Without it, the recovery kit gives chosen administrators access to emergency accounts from an encrypted file that opens offline.

Can it work with Active Directory and single sign-on?

Yes. Add any number of AD or LDAP domains and OpenID Connect providers. Users sign in with their usual accounts, their role comes from their groups, and leavers are disabled at the next sync.

Can our scripts and tools get passwords from it?

Yes, through the Credential API. Each application gets its own key, allowed addresses and allowed accounts, and every fetch is audited.

Is it possible to tamper with the recordings or logs?

Each recording's hash is sealed into an HMAC-chained audit trail, so any change shows up when the recording is replayed or the chain is checked. For an off-box copy, send the audit log to your SIEM as well.

What do I need to run it?

A VM or server with at least 2 vCPU, 4 GB of memory and 40 GB of disk, on VMware, Hyper-V, Proxmox, KVM, Nutanix AHV or bare metal. See Deployment.
